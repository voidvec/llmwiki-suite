# Hacker News 发布时机探测小结（W2）

> 目的：在 W4 硬发布前校准「周二 PT 锚点」的精确含义，补齐账号门槛与值守节奏。
> 来源：2026-09-01 网络调研（3 篇 HN 发布实战指南/社区规则复核）。

---

## 1. 账号门槛（前置，必须提前做）

| 门槛 | 数值 | 含义 |
|------|------|------|
| **最低 karma 可发 Show HN** | ~5 karma | 低于此无法提交 Show HN |
| **推荐起点** | 50-100 karma + 账号龄 >2 周 | 冷启动无历史 → 算法压权 |
| **历史评论** | ≥ 数条相关领域评论 | 账号只有 1-2 评论也显 spam |
| **绿色考察期** | 新号 14 天（投票/发帖可能不计） | 建议养号 >14 天再发 |

> ⚠️ **对我们的硬约束**：W4 发布时主理人的 HN 账号须 >14 天 + ≥50 karma + 有评论史。
> 若当前账号不满足 → 立即开始**养号**（在 Show HN/开源/回顾类帖下输出高质量评论），
> 最迟 W3 底达到 50-100 karma。**这是 W4 能否发布的前提，不可临场解决。**
> **养号执行计划（20 天时间线 / 选帖主题池 / 评论公式 / 验收检查点）见 `docs/hn-account-growth.md`。**

## 2. 最佳窗口（校准原「周二 PT」锚点）

| 结论 | 数值 |
|------|------|
| 最佳 | **周二～周四 · 06:00-09:00 PT**（= 美东 9:00am-12:00pm 早高峰） |
| 次选 | 周一-周三 8am-12pm ET |
| 最差 | 周五下午 / 周末 / 节假日 |

- 我当前预案「周二 PT」**落在最佳窗口内**（PT 06:00 = 北京 21:00，或 PT 09:00 = 北京 次日 00:00）。
- **修正**：明确锚点 = **周二 06:00-09:00 PT**，并在 W4 执行前一天把 3 小时值守空出来。

## 3. 发布结构（决定成败）

| 要素 | 规则 |
|------|------|
| **标题** | `Show HN: {产品名} - 一句话技术描述`，**<70 字符**（另一源 <91）→ 取保守 ≤70；无营销词/感叹号/emoji |
| **正文（首条评论）** | 发帖后**同账号立即回复**第一层：为什么做、解决什么问题、给谁、求什么反馈（意外比主页正文更重要） |
| **回复节奏** | 前 30 分钟逐条回；整体**值守 2-3 小时**（成本只后续 30min/条） |
| **当天纪律** | 当天不再发任何内容；多帖稀释信誉 + 触发 spam 过滤器 |
| **禁止** | 找朋友/外界拉票（vote ring 检测，检测到封号+域名连带惩罚）；同 IP 投票不算；重复贴间隔 ~1 年 |

## 4. 与我们预案的对照与修正

| 现有预案（release-plan.md） | 需要修正 |
|------|------|
| 「周二 PT 时间锚点」 | ✅ 校准为「**周二 06:00-09:00 PT**」（落在最佳窗口） |
| 「48h 回复窗口」 | ⚠️ 改为「**发布后 3 小时值守 + 48h 台账**」（前 30 分钟 high-freq 必须响应） |
| 「发布后 48h 复盘」 | 保留 +「发布后首条评论即发」步骤 |
| 未提及养号 | ✅ **新增：D8 前置条件 = HN 主账号 karma ≥50 + 龄 >14 天 + 评论史**；不满足→立即养号（W3 底线） |

---

## 4. 结论（交付给 release-plan 的修订点）

1. 发布窗口：**周二 06:00-09:00 PT**（W4）。
2. **前置硬门槛**：W3 底主账号 karma ≥50 + >14 天 + 有评论史——不满足则 W4 顺延（宁缺毋滥）。
3. 发布日流程：发帖 → 立即首条回复（why/how/feedback）→ 30 分钟级回响应 → 台账。
4. 当天不双发其他渠道内容（与「对比帖同日/次日」预案冲突——**对比帖应改为次日**，避免制品同天平摊信誉）。

> 待主理人拍板：①是否把对比帖改为「次日」（避免同日双发）；②是否提前开始养号（如需当前账号状态）。
