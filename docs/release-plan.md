## 2. 发布日 Checklist（D8 执行单）

### 发布前 48h（周一 PT）
- [ ] HN 终稿人审通过（主理人），标题 A/B 定稿（无临场改稿）
- [ ] 对比帖终稿人审通过
- [ ] 发布账号/环境验证（HN 账号 karma/age 合规、PyPI token、GitHub release 权限）

### 发布日（周二 PT）
- [ ] 打 `v0.1.7` tag + CHANGELOG 更新 + GitHub Release
- [ ] `python -m build` + `twine upload`（PyPI）
- [ ] 发布 HN 主帖（标题取 A1，正文按终稿）
- [ ] 首条评论自贴对比帖要点 + 指向完整对比文
- [ ] Telegram 保底 announce（指向 HN）

### 发布后 48h（周三-周四）
- [ ] 每 3-4h 巡查 HN 评论区（前 24h 高频）
- [ ] 记录回复台账：疑问→回复；建议→进 Backlog；defect→进 issue
- [ ] 首轮效果化：把「数字」整理进周报

### 发布后 48h 复盘（周五 PT）
- [ ] 对 4 类指标：issue/PR 数、star、下载、suggest 采纳 → 和 W9 验收门槛（§5）对齐
- [ ] 决定：继续补充 / 二波微调 / 若零信号→触发止损评估（W9 pivot 决策点预演）

## 3. 回复窗口策略（防空窗）

- 发布后 **48 小时**是第一信号带：前 12h 每小时小自查，后续 3-4h 一次。
- 台账：`docs/release-response-ledger.md`（可选创建，记录每条评论/回复/转化）。
- 禁止：发布后 48h 内大改主贴正文（HN 不留痕，改动会被判定为 SEO/垃圾）；素材缺失只补评论区。

## 4. 风险与降级

| 风险 | 应对 |
|------|------|
| HN 发布即沉帖（algorithm 冷启动） | 首帖标题取 A1（机制向）减被「标题党」误判；可换 B1 重试一次（重试 ≤2） |
| PyPI 429 / Twine 失败 | 发布日前一天先跑 dry-run；失败 delay 2h 重试 |
| 账号权限不足（HN 新号） | Show HN 有 karma/age 门槛 → 提前注册/养号，W4 前验证 |
| 外部零信号 | 按合同 §5 止损线：star<20 无 PR 重试 2 次无效 → pivot |
