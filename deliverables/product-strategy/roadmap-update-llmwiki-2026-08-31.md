## 📌 TL;DR（执行摘要）

- **核心发现**：llmwiki-suite 处于「**工程健康、市场零观测**」的矛盾状态——8 天发布 7 版（0.1.0→0.1.6）、召回基线 recall@4=100%、零核心依赖，但 GitHub 0 star/0 fork、PyPI 近月下载 475 次且近似一次性验证性流量。
- **市场窗口**：PKM×Agentic AI 市场 2028 年预计达 £42 亿（CAGR 27%，Business2.0 2026）；Obsidian 2026-02 破 150 万用户（YoY +22%）并发布 CLI；Karpathy 2026-04 发布 LLM-wiki Gist 8 天 5000+ stars——情绪高潮在 2026 年 4-5 月，**4-6 个月窗口期**，错过即错过品类先机。
- **关键决策**：最高优先级**不是加功能，而是把「自证工程」转为「市场验证」**：Wave 1（1-6 周）建立四类指标观测 + 发布「零依赖健康分仪表盘」（开源稀缺卖点）；Wave 2（7-12 周）市场起飞（HN/PH/Reddit + repo 20-100 star）；Wave 3（13-24 周）落地 L1 记忆引擎（suggest 采纳率 ≥30%）。
- **定位升级**：从「本地 RAG 工具」→「**知识库自进化基础设施**」（别和 RAG 抢检索、和 Obsidian 抢工作流、和记忆层抢知识资产）。
- **下一步**：确认 Wave 1 开工顺序（曝光监控先行，健康分与 README 重写并行），将 P1 团队锁责挂接 OKR。

## 3. 用户反馈摘要（来自瑞思）

| Persona | 人设 | 核心痛点 | 选用 llmwiki 的动机 |
|---|---|---|---|
| P1 技术博主 | 1000+ 篇笔记的 Obsidian second brain 用户 | 笔记多找不到、双链全靠手动、RAG 回答不沉淀 | 编译式沉淀素材池、零编辑器依赖、持续编译 |
| P2 后端/DevOps 本地库管理员 | 本地服务器、重隐私、要自动化 | 隐私红线（不子上云）、手工维护索引/断链、旧文档过时 | 纯本地零依赖可审计、lint 自动巡检、CLI+四通道降维护税 |
| P03 普通开发者 | LLM 尝鲜 | RAG 配置劝退（向量库/chunking）、小模型幻觉 | pip 一条命令接入、自带 eval 自证检索质量 |

**需求趋势**：检索困境取代收集困境（80% 笔记一周后不被再看）；PKM 大规模采用后大规模弃用（维护税）；RAG 在个人规模「知识复利不复利」；碎片化+隐私是硬需求；「AI 管结构、人管意义」。

**用户研究结论**：**L1=转化引擎、L2=留存引擎、L3=忠诚引擎**；主张「用一天就安装、用一周就依赖、用一个月离不开、用三个月愿意为主动进化买单」；底线是用户保有内容掌控权。

## 4. 竞品动态（来自竞析）

- 圈层 A：Obsidian+AI 插件（威胁高）——占「笔记×LLM」心智，但只有编辑器+检索插件，无编译管线/lint/eval。
- 圈层 B：RAG/知识库——AnythingLLM、Dify、RAGFlow（威胁中）——同抢「本地私有知识库」，查询时 Retrieval 无资产沉淀、部署重（Docker/向量库/模型）。
- 圈层 C：Agent 记忆层——Letta/MemGPT、Cognee、Zep/Graphiti（威胁渐升）——2025 记忆产业爆发（企业级资方背书），面对开发者 Agent 记忆，非用户可读的 IAM 知识资产；L1-L3 提纲可借鉴。
- 圈层 D：LlmWiki 同源——Karpathy Gist（2026-04 引爆）与 nashsu 桌面 demo（威胁中）：方法论抢心智，但缺工程化 CLI、多通道、可 lint/eval 的套件。「你有的他却没有」。

**差异化四板斧**：① 定义「编译系」品类（导入期沉淀可读可审计资产 vs RAG 查询期检索）；② lint/eval 可观测性防漂移护城河（断链/孤立页/摘要漂移/错误固化，RAG 无编译产物、Obsidian 插件碎片化）；③ IM 多通道（Telegram/企微/飞书/微信）占国内工作流；④ pip 零依赖轻量接入 vs Docker 重型部署。

## 6. 指标/KPI 体系（L0 就绪、形态建议）

**一组【曝光】**
- GitHub：star/star-rate、clone、issue/PR 分类、fork
- PyPI：日/周下载（需去重「一次性验证」口径）、上游群组
- 官方/公众号：文章阅读、launch 引流
**二组【激活/转化】**（体验埋点，全匿名）
- 安装→首次 ingest（≥80%）
- 首次 query（≥40%）
- 首次 query→DAC 活跃（D7 ≥10% 起步）
- 首次晚自习（lint/health）（护栏性调用）
**三组【防漂移】
- recall@4≥0.85 / MRR≥0.80，CI 门禁，每次 PR 回归
**四组【渠道】
- 4 通道日活跃/调用失败率/对话质量；「IM→web 复用」型案例
**五组【L1 观测事件】
- observe（扫描条数、类型、坏链）/ nightly（产出数、空簿率、耗时 P95）/ suggest（展示/采纳/采纳率≥30%、驳回率<40%）/回流闭环率（建议→采纳→被 query 命中）

## 9. 加速版时间线（AI 效率版 · 9 周收口）

> 因 AI 编码/物料生成效率高，原 24 周 → **9 周收口**。靠两条杠杆：①物料/文档/仪表盘初版全部 LLM 批量生成（W1-2 集中产出、人工只审关键件）；②发布周与 L1 开发并行（不互相等待）。主线先把「市场可见」做出来（物料+健康分 MVP+发布），深度功能（L1）降档为第二主线、由外部反馈驱动。

### 9.2 本阶段 Non-Goals（必砍/降级清单）

1. 健康分只做 MVP 基础版（0-100 简单规则、单文件 HTML/JSON，对外定性「经验版 Beta」），不做可视化/图表库。
2. 漏斗埋点做最简：只上线 3 事件（安装下载走 PyPI API、首次运行、eval/suggest 采纳各 1 次），不做全链路逐步漏斗。
3. L1 只做 observe + suggest 两命令精简版；不做 nightly 智能汇总、L2 详细设计（留占位到后 Wave）。
4. README 只做英文版（娱乐中文双语）；iLink 国内通道整体后置 Wave 3；Telegram 只保底不运营。
5. 不做多平台长跑（PH 多维选、社群运营长期战役）；**只打 HN 主帖 + 对比文**。
6. 明确不做向量/embedding 系统设计；retention 完整基线降为「可观测周报」。

| 健康分打磨不足、数据偏差 | 中 | 以「经验 v1 Beta」对外定性「健康度参考值」，配「首次公开 eval 报告」补信任 |
| 外部 2 周无响应、star 不涨 | 高 | **止损 pivot**：当「star<20 且无外部 PR 且重试 2 次无效果」→ 收回转做纯工程打磨（回忆指标 CI）+ 国内 iLink 前置（社区承接）；保留 pivot 决策点 W9 |
| 硬指标失真（PyPI 475 一次性下载≈测量误差） | 中 | 收敛硬验收：外部 issue/PR ≥3、suggest 采纳 ≥30% 为硬指标；star/下载仅作参考 |

### 9.4 一句话执行建议

W1-2 用 LLM 批量产出英文物料 + 健康分 MVP 先行，W4 硬发布、W4-6 专注外部响应（留 1-2 周硬缓冲）；W7-9 若外部有信号→转向 L1 采纳闭环，把它做成「市场可见」的最小成果；若零信号→止损 pivot 回工程/国内池，**不为打卡而堆功能**。
